# 已到账账单核对

入口 `/pangu-sales/?view=profit-bills`。核对账务明细的“结算”工作表、PO 明细和 PO 聚合账单。比较按店铺、PO 和原币分别进行，不换汇、不累计三种展示方式为收入，也不改变毛利计算。

`profit_bill_files` 保存文件名、店铺、来源类型、上传 XLSX 字节 SHA256 与导入时间；ZIP 使用每个 XLSX 的 SHA256。`profit_bill_rows` 保存解析后的逐笔原始字段和金额，文件与明细只新增，不覆盖旧依据。原始 XLSX 文件字节未存入数据库。无文件字节的内部程序批次使用解析内容摘要，页面明确区分摘要口径。明细序号是解析后记录序号，不是 Excel 物理行号。

相同店铺、来源和 SHA256 的文件重复导入跳过，不改变优先级。同来源每个业务键采用最后一个新文件的记录；未出现记录保留，不将增量文件当作全量快照。流水以结算流水 ID 为键，聚合以 PO 为键；同文件重复业务键拒绝，不能以最后一行静默覆盖。整个文件包原子保存；普通账单导入的原始台账与核对依据在同一事务中保存。

现有历史共用结算表不能反推每条记录来自哪一份原文件，因此不上线时伪造来源。页面“导入核对依据”只接受上述三类 XLSX 或只含这三类文件的 ZIP，保存独立依据，不更新任何 `temu_profit_*` 表，也不改待处理记录和原账单导入历史。正常账单导入自动保存三类来源依据，其他五类账单沿用原有流程。

比较销售回款、运费回款、销售冲回、运费冲回四个金额；核对金额保留 Excel 单元格的十进制文本，直接写入 PostgreSQL numeric，不经过 float64 求和；JSON / CSV 输出金额为十进制文本，避免浏览器浮点舍入。聚合中的冲回比较值为 `-ABS(原金额)`，原始字段保留。三份来源全部存在、四类款项分别相等，且账务明细与 PO 明细的每个流水 ID、PO、币种、交易类型和金额对应时，才显示“金额一致”。净额相同不能抵销款项差异。缺少来源显示未提供，相关差额为空，不补零。聚合文件已出现但四项金额有空白时保留 NULL，并列为字段缺失；内部程序明确提供的数值零仍为零。

PO / 币种缺失、同一 PO 多币种、未识别交易类型、金额方向异常及折后回款口径未确认显示待核对。PO 聚合文件没有账期字段，按当前累计依据比较，不能证明某个月账单或整个订单生命周期已经完整。核对结果不会自动修正财务台账。

接口：

- `GET /api/profit/bill-comparison?shop_key=&currency=&status=&q=&page=&page_size=`：列表、当前筛选状态数量及店铺最近 30 个依据文件；状态为 matched / difference / missing / review。查询 PO，按字面匹配百分号和下划线。每页默认 30、最多 200。
- 同接口 `export=1`：按当前筛选导出所有分页的 PO / 币种及四项金额、差额、来源文件和 SHA256。文本字段作电子表格公式转义。
- `GET /api/profit/bill-comparison/detail?shop_key=&po_no=&currency=&page=`：当前有效逐笔依据、原始字段和文件摘要，每页 100 条。指定 `file_id` 时读取该店铺历史文件当时的所有明细，包含已被后续文件替代的业务键。
- `POST /api/profit/bill-evidence/import`：Multipart 文件、shop_key 和可选 table；32 MB 上传限制。须传 `X-Pangu-Request: finance`，Origin 须同源。整个包验证和保存失败时回滚。该接口不写旧的账单导入记录，依据文件本身保留导入历史。
