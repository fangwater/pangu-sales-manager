# 《TEMU数据来源.docx》实现评估与报表更新

评估日期：2026-10-07。对照文件为项目 `TEMU利润计算/TEMU数据来源.docx`，同时核对原始 Excel 表头、结算流水 ID / 金额、线上数据库和现有计算代码。

总体结论：账单导入、结算流水去重及大部分费用来源映射正确；完整的订单费用归因、退款件数、待结算回补、商品成本和毛利尚未实现。原来的“利润”页面主要提供账单汇总，名称容易让人误以为已经形成完整利润报表。本次将页面分为财务总览、SKU 财务分析、待结算检查和账单导入，明确已知金额与缺少的数据。

文档还需澄清两点：

1. “基础信息（9 列）”实际列举了 11 项，建议按实际字段重新编号；“费用时间”“付款时间”“订单时间”需要明确具体业务时间。
2. “销售回款已减优惠 / 运费回款已减优惠”是独立交易金额、替代回款口径，还是优惠后的结果，文档没有说明。当前样本这些列均为零；新报表遇到非零折后列会暂停净待回款合计，避免将两套金额错误相加或重复扣减。

新版报表提供：

- 财务总览：指标卡、回款和费用趋势、费用构成图、销量与价格覆盖图、数据完整性检查。
- 店铺及自定义日期筛选、日 / 周 / 月分桶，日期筛选在分桶前生效。
- 期间明细默认精简，费用可展开；CSV 含完整已接入费用、覆盖率及缺失字段说明。
- SKU 财务分析：销售回款排名、价格覆盖、搜索、排序及导出；无已到账记录的 SKU 不显示为零回款。
- 待结算检查：快照日期、净待回款、待出账面单、已到账重叠 PO / 金额、SKU 构成及导出。
- 明确区分无账单、已知零金额、尚未接入成本和辅助估算；含非 USD / 未知币种时暂停 USD 金额合计。

验证使用独立测试数据库运行 Go 测试，未在业务数据库中插入测试数据；用只读 PostgreSQL 连接采集真实汇总结果。浏览器验证覆盖桌面 / 手机布局、日期筛选、店铺切换、缺失数据、金额一致性、费用展开、CSV 下载、SKU 搜索及待结算重叠。业务数据库保留全部原始账单，未执行自动核销或更改历史价格。

优先待办：补齐最近月份及另一店铺的账单；修复库存同步；准确订单时间与持续价格回填；订单费用归因和结算回补；成本模型与退款数量。完成这些后，再计算订单与 SKU 毛利。
